# 《环境与资源保护法》下载与登录问题排查

排查日期：2026-11-09（北京时间）。源码：`62221df`，对应 Release `v2.0.2`。

课程：https://www.icourse163.org/course/SHUFE-1486311164

## 已确认的下载阻断原因

匿名调用现有客户端即可解析本学期 `1488199471`，共 19 个章节、109 个视频、43 份课件。章节数包含资料与练习章节。

抽测第 1、55、109 个视频，资源授权接口都成功返回，`videoSignDto.status=0`，视频地址接口也都返回 `code=0`。但三个样本的全部三个清晰度都是 HLS，且都带 `e=true`、`secondaryEncrypt=true`，同时存在 `k` 字段。

`app/icourse_api.py:419` 在任何视频条目包含 `k` 或 `e=true` 时主动抛出 `PaidCourseError`，提示“当前视频为加密内容（付费课程），本工具仅支持免费公开课”。报错由下载器主动生成，并非本次请求收到源站的登录失效错误。

课程页同时声明 `chargable="false"`、`price="0"`、`originalPrice="0"`。因此，“存在加密”不能推导为“付费课程”，当前提示混淆了两个概念。

对照测试南京大学《普通天文学》的首个视频：同为匿名请求，授权与视频地址接口成功，返回未加密的 MP4/FLV，现有检查不会阻断。

以上只抽测指定样本，未检查全部 109 个视频，没有下载课程视频。

## 为什么不能直接删掉加密判断

`app/downloader.py:306` 还会拒绝播放列表中非 `NONE` 的加密方法。当前源码没有实现这门课所返回的二次加密视频处理流程。移除第一处报错不能证明能生成可播放文件，修好账户验证也不等于补齐视频格式支持。

## 已确认的登录校验缺陷

`app/ui.py:549` 将登录窗口导出的 Cookie 记录转成 requests 会话；随后 `app/ui.py:552` 调用 `CourseClient.verify_identity()`。

`app/icourse_api.py:465` 的验证实现仅抓取首页原始 HTML，用正则提取 `window.webUser = {...}`，再按严格 JSON 解析。没有匹配到对象、JSON 解析失败、或者对象没有 id，都会统一提示“当前登录信息未通过验证，请重新登录”。这个错误本身不能区分密码错误、Cookie 导出或属性问题、页面格式不匹配。

用户在内置浏览器手动登录后，首页已显示“个人中心”和用户头像。检查该页面的内联 script，实际存在 `window.webUser = {...}`，但它是 JavaScript 对象字面量：`rightsTime`、`id`、`nickName`、`roles` 等字段名不带引号。正则能匹配到对象，严格 JSON 解析失败。这已确认是一个会导致正常登录被误判的源码缺陷。

将相同语法的虚构身份注入现有 `verify_identity()`，可稳定复现原报错：

```javascript
window.webUser = {
    rightsTime: "0", id: "42", nickName: "Example", roles: [], end_key: 0
};
```

`app/icourse_api.py:199` 的课程解析也使用 JSON 处理该对象；其单引号替换不能解决未加引号的字段名。同样语法的复现中，`load_course()` 把 `web_user_id` 设为空串。只修登录入口、遗漏此处，会继续影响登录后资源签名。

修复建议：统一使用不执行页面代码的 JavaScript 对象解析器，在身份验证和课程解析两处复用；覆盖真实对象格式、严格 JSON 格式、游客页、特殊字符和无效输入的回归测试。避免使用 eval 或把 Cookie 存在直接视为已验证登录。

`app/login.py:111` 的 `_read_records()` 与 `_read_cookies()` 在支持的输入形式上也有差异，但本次没有证据证明 WebView2 Cookie 导出发生错误，不将它作为已确认根因。

上游 `docs/RELEASE_2.0.md:82` 明确说明未完成真实账户登录端到端验证。

## 证据与范围

脱敏接口摘要保存在 `diagnostics/SHUFE-1486311164-2026-11-09.json`。只记录状态、资源编号、格式与加密标记，不保存密码、Cookie、播放签名、密钥内容或完整视频地址。

本次未修改生产代码，未安装或替换用户的 exe。浏览器自动提交未成功，清空输入后由用户手动完成登录。已核对真实登录页面格式，并用虚构身份复现两个解析缺陷；没有完成 WebView2 登录窗口到 requests 的 Cookie 传递端到端测试，也没有测试登录后视频接口是否返回不同格式。

结论：登录校验存在已确认的对象格式解析错误；目标课程匿名接口返回的加密视频又超出现有下载能力。两处问题需要分别处理，不能承诺只修登录就能下载该课程。
